# Domain docs

This repo uses one domain context. Its glossary lives at `GLOSSARY.md`;
system-wide architecture decisions live in `docs/adr/`.

Before exploring or changing behavior, read the glossary if it exists and
ADRs relevant to the area. Use the glossary's terms in issue titles,
tests, proposals, and code discussions. If a term is missing or ambiguous,
resolve it through domain modeling and add it when agreed.

Create the glossary or ADR directory only when there is a term or decision
to record. If an intended change conflicts with an ADR, call out that
conflict and revisit the decision explicitly.
